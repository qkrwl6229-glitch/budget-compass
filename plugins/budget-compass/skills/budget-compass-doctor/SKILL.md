# 사업비 나침반 Doctor

사용자가 요청했을 때만 실행하는 **읽기 전용 점검**이다. 업무 답변마다 붙이지 않는다.
다운로드·설치·파일 교체·GitHub 게시·권한 변경을 실행하지 않는다. 계정 토큰이나 비공개 자료를 요구하지 않는다.

## 범위
| 요청 | 점검 범위 |
|---|---|
| 그냥 "점검해줘" | 설치 버전 + 기본 점검 범위(자주 쓰는 R&D·세무 조문, RCMS 매뉴얼) |
| 주제 지정 ("회의비 기준만", "원천징수만") | 그 주제의 조문만 (`../budget-compass/references/index.md` 에서 주제 → 조문 확인) |
| "전체 점검" | 카탈로그의 모든 문서 (판본 단위) |

## 1. 플러그인 버전 점검
1. 설치 버전: 호스트가 설치 버전을 알려주면 그것을 쓴다. 없으면 [references/installed-release.md](references/installed-release.md) 의 `package_version`·`source_commit`·`build` 를 읽는다. 둘이 다르거나 읽을 수 없으면 플러그인 상세 화면의 버전을 확인하도록 안내한다.
2. 최신 안정판: 웹을 쓸 수 있으면 `latest_stable_api` (GitHub Releases 최신 안정판) 또는 `releases_url` 을 연다. 초안·시험판(prerelease)과 `main` 브랜치 커밋은 안정판이 아니다.
3. 비교: 버전을 숫자 단위 SemVer 로 비교한다 (0.10.0 > 0.9.0).

| 결과 | 조건 |
|---|---|
| `업데이트 있음` | 최신 안정판 > 설치 버전 |
| `확인한 안정판과 같음` | 최신 안정판 = 설치 버전 |
| `설치본이 더 새로움` | 설치 버전 > 최신 안정판 (시험판·저장소 직접 설치 등) |
| `배포판 확인 불가` | 웹 없음, 저장소·릴리스 접근 불가, 안정판이 하나도 없음, 시험판만 있음 — **최신판을 추정하지 않는다** |

## 2. 공식 규정·매뉴얼 점검
[references/source-catalog.md](references/source-catalog.md) 의 수록 판본을 공식 현행판과 비교한다.
1. 문서마다 `현행·연혁 확인 주소`를 열어 현재 시행 중인 번호·시행일을 읽는다. 시행 예정 판본이 보이면 따로 적는다.
2. 번호·시행일이 수록 판본과 같으면 → `해당 조문 일치` (판본이 같으므로 조문 본문은 다시 받지 않는다).
3. 다르면 → 점검 범위의 조문만 새 판본에서 열어 `../budget-compass/laws/<id>/<조문>.md` 본문과 비교한다.
4. 사용자가 과거 사건을 말했으면 그 날짜에 시행된 판본·부칙(경과조치)을 확인한다.
5. RCMS 매뉴얼은 문서 판본·게시일과 작성 기관(적용 전문기관)을 확인한다. 과제별 허용 목록·이체 한도는 공개 자료로 확인할 수 없다.

| 결과 | 조건 |
|---|---|
| `해당 조문 일치` | 현행 판본이 수록 판본과 같음 (또는 새 판본이지만 해당 조문 문구가 같음) |
| `개정 확인` | 현행 판본에서 해당 조문 문구가 달라짐 → 바뀐 요지와 시행일 |
| `개정판 시행 예정` | 새 판본이 공포됐지만 아직 시행 전 |
| `판본 변경, 조항 영향 미확인` | 새 판본이 있는데 해당 조문을 열어 비교하지 못함 |
| `사건일 적용판 확인 필요` | 사용자가 말한 사건일이 수록 판본 시행일보다 이전 |
| `원문 확인 불가` | 웹 없음 또는 원문이 열리지 않음 → 수록 판본만 표시 |

## 3. 보고 형식
```
설치 버전   v0.5.0 · 이 스킬의 번들 정보 기준 (build, commit)
배포 버전   v0.5.x 안정판 · 릴리스 주소 · 조회일 YYYY-MM-DD   ← 확인한 값만
규정 점검   연구개발비 사용 기준 제25조: 해당 조문 일치 (과학기술정보통신부고시 제2026-38호, 시행 2026-05-06)
            부가가치세법 제29조: …
            RCMS 매뉴얼: 2023-12-19 판 (KEIT) · 과제별 허용 목록 미확인
조치        …
```
- 두 점검은 **독립**이다. 예: 플러그인 배포판은 같은데 규정은 바뀌었으면 "플러그인 업데이트 없음 / 수록 규정에는 개정 반영 필요"를 함께 쓴다.
- 확인하지 못한 값은 빈칸이 아니라 `확인 불가`와 이유로 쓴다. 조회일을 붙인다.

## 4. 조치 안내
[references/update-channels.md](references/update-channels.md) 에서 사용자의 설치 유형에 맞는 방법을 알려준다. 설치 유형을 모르면 한 번만 묻거나 세 가지를 짧게 모두 보여준다.
- 규정이 바뀌었으면: 새 릴리스가 나오기 전에도 업무 스킬이 웹으로 새 원문을 근거로 답할 수 있음을 알린다. 설치 파일은 자동으로 바뀌지 않는다.
- 배포자에게 알릴 내용이 있으면 저장소 이슈로 알려 달라고 안내할 수 있다 (Doctor 가 직접 올리지 않는다).
